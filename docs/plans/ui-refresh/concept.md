# UI Refresh Concept

## Summary

This plan defines a visual and structural refresh for the web app. The goal is to replace the current utility-first MVP presentation with a cleaner, more distinctive interface built around a bento-style layout system, a stronger color direction, a light/dark theme toggle, and broader usage of Base UI-backed components.

## Problem

The current interface is functional, but it still reads like an MVP shell. Layout sections are mostly stacked cards, the visual hierarchy is conservative, and the color system is not yet strong enough to give ObjectAtlas a memorable product identity. The user wants a cleaner and more intentional presentation rather than incremental cosmetic tweaks.

## Goals

- Establish a new page layout language with bento-style grouping and clearer visual hierarchy
- Introduce a cleaner, solid color system with both light and dark themes
- Expand Base UI usage so shared controls feel more consistent and deliberate
- Keep the existing product flows intact while improving the shell and presentation

## MVP Scope

The MVP for this redesign should include:

- a redesigned global app shell for the home page and shared navigation
- a reusable bento-style section system for top-level marketing and workspace framing
- a defined light theme and dark theme token set
- a working light/dark theme toggle persisted in the browser
- Base UI-backed control primitives for the shared UI surfaces used in the refreshed layout
- visual updates focused on layout, surfaces, spacing, color, and hierarchy rather than feature expansion

## Ideal Scenario

After the first redesign ships, the same design system can evolve toward:

- broader Base UI coverage for forms, menus, popovers, switches, and future overlays
- reusable semantic layout primitives for dashboards, public object pages, and about pages
- richer motion and transitions between theme and layout states
- a stronger design-token layer shared across the app
- a polished public-facing visual identity that scales to future collection and provenance features

## Non-Goals

- Rebuilding the product architecture
- Adding new backend product features
- Reworking object CRUD or media business rules
- Solving every future design system need in one pass

## User Flow

The user opens the web app and immediately lands in a new layout with stronger visual grouping and cleaner navigation. They can switch between light and dark themes from a visible toggle, browse object records in the refreshed workspace shell, and continue using the same record-management flows without relearning the product structure.

## UX Notes

- The redesign should feel clean and solid, not glossy or overly decorative
- Bento layout should improve hierarchy and scanning, not become visual clutter
- Dark mode should be designed intentionally rather than generated by inverting colors
- The theme toggle should be easy to find, quick to use, and persistent between visits
- The refreshed layout should still prioritize mobile behavior first even if the visual system becomes more expressive
- Shared controls should feel systematized through Base UI-backed wrappers rather than one-off styling

## Acceptance Criteria

- [ ] The home page and shared shell use a noticeably new layout structure rather than the current stacked-card composition
- [ ] The UI has a defined light theme and dark theme with intentional colors in both modes
- [ ] Users can toggle theme from the interface and the choice persists locally
- [ ] The refreshed shell uses Base UI-backed primitives for shared interactive controls
- [ ] Existing object management flows remain usable after the redesign

## Open Questions

- Should the theme toggle live only in the navbar, or also appear inside a future settings surface?
- Should the first redesign include the public object page layout, or focus only on the main app shell and workspace?
